# 作业：React 个人学习计划板

## 目标

使用 React 制作一个“个人学习计划板”，练习组件拆分、props、列表渲染、状态与事件、派生数据、条件渲染，以及响应式和可访问的界面设计。

完成作业前请阅读：

- `materials/01-react-and-jsx.md`
- `materials/02-state-and-events.md`
- `materials/03-responsive-and-accessible-ui.md`

## 要求

1. 在 `work/<你的用户UUID>/afb33209-4b05-4ecc-ba74-1c70ea57ef8a/` 中创建可独立运行的 React 项目，推荐使用 Vite。用户 UUID 以 `learn2ai-context context` 返回的信息为准。
2. 使用本地 JavaScript 数组提供至少 8 个学习任务。每个任务包含稳定且唯一的 `id`、标题、分类、预计时长和初始完成状态；不接入后端或外部 API。
3. 至少拆分出 `Header`、`ProgressSummary`、`FilterBar`、`TaskList` 和 `TaskCard` 组件。任务卡片通过 props 接收数据，列表使用 `map` 渲染，并以任务 `id` 作为 `key`。
4. 提供一个受控搜索框，可按任务标题实时筛选；再提供“全部”“未完成”“已完成”三个状态筛选选项。搜索条件和状态条件必须同时生效。
5. 每个任务提供“标记完成”或“设为未完成”按钮。点击后以不可变方式更新任务数组，不得直接修改原数组或任务对象。
6. 页面实时显示“已完成数量 / 总数量”和完成百分比。统计值必须由任务状态计算得到，不应另存为一份独立状态。
7. 当筛选结果为空时显示明确提示，并提供“清除筛选”按钮；清除后恢复全部任务。按钮在没有可清除条件时应处于禁用状态。
8. 使用语义化 HTML。页面有一个清晰的 `h1`，表单控件有可见标签，执行操作使用 `button`；所有交互可通过键盘完成，并提供清晰的 `:focus-visible` 样式。
9. 使用 CSS 实现响应式布局。在约 375px 手机宽度和 1280px 桌面宽度下均不得出现横向滚动、文字遮挡或控件重叠；状态不能只依赖颜色表达。
10. 在项目目录添加 `README.md`，写明安装与启动命令、组件与状态设计，以及下方验证步骤的实际结果。

## 验证步骤

提交前逐项验证，并在 `README.md` 中如实记录结果：

1. 运行 `npm install`、`npm run build` 和项目已有的 `npm run lint`，记录每条命令是否通过。
2. 输入一个能命中的关键词，再依次切换“全部”“未完成”“已完成”，确认两个筛选条件会组合生效。
3. 切换至少两个任务的完成状态，确认任务状态、完成数量和百分比同步更新；刷新页面后恢复初始数据是允许的。
4. 制造一次无结果状态，确认提示出现；点击“清除筛选”，确认完整列表恢复。
5. 在约 375px 和 1280px 两种视口下检查布局，并仅使用 Tab、Shift+Tab、Enter 或 Space 操作全部交互控件，确认焦点始终可见。
6. 检查浏览器控制台，确认没有 React `key` 警告或运行时错误。

## 评分关注点

- 功能完整性：搜索、组合筛选、状态切换、派生统计、空状态和清除功能均正确。
- React 实践：组件职责清晰，正确使用 props、状态和稳定 `key`，以不可变方式更新数据，未存储可直接计算的冗余状态。
- 界面质量：信息层级清楚，在手机与桌面端均易于浏览和操作。
- 可访问性：语义结构、可见标签、键盘操作、焦点样式和非颜色状态提示符合要求。
- 工程质量：目录清晰，构建和检查通过，README 能准确说明实现与验证过程。
